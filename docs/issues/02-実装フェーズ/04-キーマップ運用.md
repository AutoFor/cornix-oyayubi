## 🎯 目的
Vial GUI を失う代わりのキーマップ運用フローを確立し、NICOLA レイヤーと共存させる。

## 📚 背景（Vial → ZMK の運用変化）
- 純正ファームでは Vial アプリでリアルタイム編集できたが、ZMK では
  **keymapファイル編集 → Actions ビルド → UF2書き込み** が基本フローになる
- リアルタイム編集の代替は **ZMK Studio**（対応にはボード定義側の `studio-rpc-usb-uart`
  スナップショット対応が必要。hitsmaxft 定義の対応状況を要確認）
- GUI編集だけなら **ZMK Keymap Editor**（nickcoutsos製、GitHub連携）も使える

## ✅ 作業項目
- [ ] 基本フロー確立: keymap 編集 → push → Actions → UF2 の一連を手順化（README化）
- [ ] ZMK Studio 対応可否を調査（対応可能なら studio 有効ビルドを試す）
- [ ] （任意）ZMK Keymap Editor で fork リポジトリを編集できるか確認
- [ ] NICOLA オン/オフキーを含むキーマップ変更が上記フローで問題なく回ることを確認

## 🏁 完了条件
- キーマップ変更が確立したフローで安全に反映できる
- NICOLA レイヤー/切替キーが運用フロー上で破綻しない
